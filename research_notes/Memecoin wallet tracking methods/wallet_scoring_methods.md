# Memecoin wallet tracking: how smart-money wallets are identified and scored on Solana (research as of Oct 2026)

Scope note: research was constrained by what vendors publish. Most tools (GMGN, Cielo, Axiom, Photon, BullX, Birdeye, Kolscan) do NOT publish their ranking or PnL formulas. Where a claim comes from a vendor-affiliated blog (e.g. MadeOnSol, which sells a competing API) or a secondary explainer, that is flagged. Statistical-method points (shrinkage, bootstrap, etc.) are NOT sourced to any wallet tool and are marked as inferences. Several fetches were thin (page text truncated by the fetch tool); I did not see full-text of the arXiv papers, only abstract-level pages.

## 1. How do GMGN, Cielo, Birdeye, Nansen, Axiom, Photon, BullX, Kolscan, Dune dashboards and similar tools define and rank "smart"/"alpha"/"KOL" wallets, and which metrics do they expose?

### Takeaway
Almost every product ranks wallets primarily on backward-looking realized PnL (30d/90d windows) with win rate and trade-count floors layered on top. Only Nansen discloses criteria categories (win rate, ROI, realized profit, token diversity, consistency) and even it publishes no numeric thresholds. GMGN, Cielo, Axiom, Photon and BullX publish no ranking methodology I could find. The most transparent public schema is Solana Tracker's API, which is the best proxy for how leaderboards are built.

### Cited Findings
- **GMGN tags (secondhand, from GMGN's agent-skill/CLI docs and explainers):** `smart_degen` = wallets GMGN's algorithm tags as having a "statistically proven" profit record; `renowned` = KOL/fund/public-figure wallets; `sniper` = bought at token launch (first-block buyers); related tags `bundler` (bot-bundled buys) and `rat_trader` (insider/sneak trading). GMGN's own checks are labelled reference-only. The actual statistical test behind "smart_degen" is not published. — [Search summary of GMGN skills docs](https://docsearch.algolia.com/mcp/docs/repo/gmgnai/gmgn-skills); [gmgn-cli README](https://cdn.jsdelivr.net/npm/gmgn-cli@1.5.2/Readme.md)
- **GMGN token-level risk fields exposed via CLI:** `smart_degen_count`, `renowned_wallets`, `rat_trader_amount_rate` (volume share from insider/sneak wallets), `bundler_trader_amount_rate`, `sniper_count`, `suspected_insider_hold_rate`, `fresh_wallet_rate`, `is_on_curve`. Wallet pages mention realized/unrealized PnL, win rate, trade style, full history, but field definitions were not in the fetched docs. On Solana the honeypot field is always null, so null must not be read as "safe". — [gmgn-cli README](https://cdn.jsdelivr.net/npm/gmgn-cli@1.5.2/Readme.md); [Search summary](https://docsearch.algolia.com/mcp/docs/repo/gmgnai/gmgn-skills)
- **Nansen (primary: Academy "Smart Money 101"):** criteria named but no numbers: minimum win rates, required ROI, realized-profit thresholds; trading diversity (number of profitable tokens, portfolio composition); consistency ("performance through downturns"). Short-term labels (30D, 90D) face higher required win rates and lower absolute profit thresholds; long-term (180D, All-Time) have more balanced win rates and higher profit requirements. Label sizes: 30D Smart Trader ~200 addresses, 90D ~410, 180D ~600, All-Time ~850, plus Smart Fund (EVM/Solana). No exclusion criteria (bots, insiders) stated on the page. — [Nansen Academy: Smart Money 101](https://academy.nansen.ai/articles/2132837-smart-money-101)
- **Nansen Solana-native labels** include Memecoin Whale (>0.1% of a leading memecoin's supply) and Top Pump.fun Memecoin Creator (top 5% of creators); Solana Smart Money also includes EVM Smart Money wallets bridged over. Specific Solana PnL/win-rate thresholds were not found. (From search summary of Nansen's Solana post and label guide; direct page fetch of the label guide returned 404.) — [Nansen: Solana live on Nansen](https://nansen.ai/post/solana-live-on-nansen); [Nansen wallet labels](https://nansen.ai/post/wallet-labels-emojis-what-do-they-mean)
- **Nansen PnL/ROI metrics exposed:** realized, unrealized, total PnL; Total ROI (incl. unrealized); Average ROI = ROI on sold tokens weighted by trade size; Win rate = share of token sales that were profitable. — [Nansen PnL guide](https://www.nansen.ai/post/understanding-nansens-pnl-tracking-a-guide-for-crypto-traders)
- **Solana Tracker `/v2/pnl/leaderboard/top` (best public schema of a leaderboard):** defaults days=90, sort=realized, minTrades=20, minInvested=$1, minDays=3, excludeArbitrage=true, pnlMode=strict. Sort options: realized, volume, days, roi, win_percentage, trades, tokens. Filters include minClosedTokens, minWinRate, minRoi, and `maxSingleTokenPct` (cap on share of PnL from one token, described as removing "one-hit wonders"). Platform filter supports axiom, bloom, photon (i.e. it can segment by which trading terminal the wallet used). Ranking covers the top 500k wallets per period. — [Solana Tracker leaderboards](https://docs.solanatracker.io/guides/pnl-v2/leaderboards.md)
- **Solana Tracker KOL leaderboard** sorts by total/realized/unrealized PnL, invested, proceeds, trades, tokens, ROI, win %, last trade. KOL = a tracked wallet linked to a public identity (Twitter handle etc.). Wallets are ranked by on-chain results, not followers. Position-level extras: daily snapshots, streaks, drawdown, best/worst days, biggest winners/losers, concentration, open exposure; identity tags KOL/bot/arbitrage/exchange/pool/developer/platform. — [Solana Tracker PnL v2 overview](https://docs.solanatracker.io/guides/pnl-v2/overview.md); [Solana Tracker leaderboards](https://docs.solanatracker.io/guides/pnl-v2/leaderboards.md)
- **Kolscan:** one explainer (Kalkine) describes a Kolscan-style KOL board with default sort by realized PnL, windows all-time/1/7/14/30/90d, metrics total PnL, realized PnL, win rate, ROI, trade count, last-trade date. NOTE: that article's content is drawn from Solana Tracker's API pages and it is unclear whether it describes kolscan.io's own internals. It also claims Pump.fun bought Kolscan in mid-2025 with no citation. I could not find kolscan.io's own methodology. — [Kalkine on Kolscan](https://kalkinemedia.com/education/guides/kolscan-how-solanas-smart-money-gets-ranked)
- **Kolscan gaming allegation:** a Change.org petition alleges KOLs manipulate trades to climb the leaderboard while copy-traders absorb losses. This is an unverified advocacy allegation, not a study. — [Change.org petition](https://www.change.org/p/ban-kolscan-io)
- **Birdeye:** wallet PnL (realized/unrealized), smart-money discovery tool, "Profitable Traders" ranked by 7-day PnL and volume. Birdeye token filters: market cap, holders, liquidity. (Secondary sources.) — [Atomic Wallet on Birdeye](https://atomicwallet.io/academy/articles/what-is-birdeye); [gts.ai Birdeye trading](https://gts.ai/defi/birdeye-trading)
- **Cielo:** third-party sources describe per-token/per-wallet realized and unrealized PnL, filterable live feed, alerts, user-built wallet lists; no published definition of "smart". A competitor blog claims none of Cielo, Birdeye or Solscan computes per-wallet win rate and that Cielo has no discovery engine (vendor-biased source, not verified against Cielo's docs). — [MadeOnSol: best Solana PnL tools](https://madeonsol.com/blog/best-solana-pnl-tracking-tools); [MadeOnSol: Cielo vs Birdeye vs Solscan](https://madeonsol.com/blog/cielo-vs-birdeye-vs-solscan-wallet-tracker-smart-money); [MadeOnSol: Nansen vs GMGN vs Cielo](https://madeonsol.com/blog/nansen-vs-gmgn-vs-cielo-smart-money-solana)
- **Axiom / BullX / Photon:** search found only feature-level descriptions (wallet tracker alerts, copy-trade with market-cap filters, 1% swap fee on BullX). No public scoring methodology, no confirmation of "avg entry market cap" or "% buys in first N minutes" metrics in their trackers. — [Medium how-to](https://medium.com/p/2eb29e935848/); [Dextools BullX tutorial](https://www.dextools.io/tutorials/how-to-use-bullx-terminal-solana-trading-tutorial-2026)
- **Dune community dashboards** are mostly market-wide profitability studies, not wallet-scoring products. Examples: CoinGecko (Dune `amount_usd`, Pump.fun + PumpSwap) counts realized PnL only, nets buys/sells per wallet per month across all tokens, does not filter bots/wash trading, and notes USD prices for illiquid memecoins may be missing/stale/distorted. — [CoinGecko Research: Pump.fun traders](https://www.coingecko.com/research/publications/pump-fun-traders-are-making-a-comeback)

### Inferences
- The industry de facto standard is: window (30d/90d) + realized PnL sort + floors (≥20 trades, ≥3 active days) + optional win-rate floor. GodsEye's rule (30d realized USD PnL, win rate bar, ≥10 closed trades) is in line with this, but its trade floor (10) is half of Solana Tracker's default (20) and Nansen's tiers add token diversity, which GodsEye's gate lacks.
- `maxSingleTokenPct` at Solana Tracker is the closest analogue to GodsEye's "no single trade >50% of profit" rule; note it is token-level (a wallet can have several trades in one token), which is arguably more correct than trade-level.
- Because vendors hide formulas, "smart money" tags from GMGN/Nansen should be treated as a candidate-discovery feed, not as validated skill labels.

### Gaps
- No official documentation found for GMGN's smart_degen criteria, Cielo's scoring, Axiom/Photon/BullX tracker metrics, or kolscan.io's own ranking logic.
- Could not verify whether any tool exposes "average entry market cap" or "% of buys in first N minutes" as a wallet-level metric; only token-level sniper/bundler percentages were confirmed (GMGN).
- Nansen label guide page returned 404; Solana-specific Smart Trader thresholds not found.
- Dune community wallet-scoring dashboards (as opposed to market-wide studies) were not located.

## 2. Which metrics are predictive of FUTURE profitability vs backward-looking? Evidence on persistence, survivorship bias, luck-vs-skill tests

### Takeaway
Direct evidence on Solana memecoin wallet persistence is thin. The closest rigorous evidence (a Hyperliquid wallet study) shows moderate rank persistence (rho 0.52 between adjacent 10-day windows), asymmetric: losers regress, top wallets hold up. Practitioner content argues for profit factor / expectancy / percentile ranks over win rate, but supplies no backtests. Most tools report only backward PnL.

### Cited Findings
- **Hyperliquid wallet persistence (arXiv 2608.04373, Aug 2026, single author, not peer-reviewed):** 147,113 wallets, 14.3M aggressive orders; wallets ranked by price movement following their aggressive orders (a markout-type measure; exact formula not visible on abstract page). Rankings persist across adjacent ten-day windows with rank correlation 0.52. Adding live activity from top-ranked wallets lifts out-of-sample R^2 of one-second returns (12.31%, +13.2%, t=9.2, ~1.6x the largest of 200 activity-matched placebo cohorts). Perp DEX, one-second horizon, not memecoins, and it does not test copying under execution delay. (A search summary of the full text additionally says persistence is asymmetric: bottom decile regresses toward zero, top decile holds, and holds among continuing wallets, not just attrition; I did not verify this against full text.) — [arXiv 2608.04373](https://arxiv.org/abs/2608.04373); [search summary of full text](https://arxiv.org/pdf/2608.04373)
- **DeFi lending persistence (Markovich, Hu, Zhang 2023, MakerDAO):** robust cross-sectional persistence in trader performance; followers key on easy-to-observe indicators (liquidations) and fail to use harder ones (past loan returns). Reported via search summary, full text not read. — [Kellogg page](https://www.kellogg.northwestern.edu/academics-research/research/detail/2023/information-processing-in-a-transparent-market-evidence-from-a)
- **Practitioner claim, no backtest:** MadeOnSol argues win rate is a poor ranking metric for memecoins; recommends profit factor = sum(wins)/|sum(losses)|; thresholds: 1.0 break-even, 1.5 net positive, >2.0 strong, typical top wallets 1.8–3.5, >4 suspicious (small sample/single outlier). Expectancy example: Wallet A 75% WR, +20% avg win, -60% avg loss, ~0% expectancy; Wallet B 45% WR, +180% win, -35% loss, ~+62% per trade. Suggests comparing 7d vs 30d percentile rank (strong on both = sustained; only 7d = hot streak). The article itself presents no data that high-PF wallets keep outperforming; author sells an API (promotional). — [MadeOnSol profit factor](https://madeonsol.com/blog/profit-factor-percentile-rank-kol-wallet-selection-solana)
- **Market-wide base rates (survivorship / noise context):** CoinGecko/Dune: share of Pump.fun+PumpSwap wallets with realized monthly profit was mostly <50% from Apr 2024 to late 2025 (low 30.08% Jun 2025), then 56.83% Feb 2026, 70.00% Mar 2026, 73.28% Apr 2026; April 2026 (3.14M wallets): 65.14% made $1–$500, only 5.37% made >$1K. Realized-only, no bot/wash filtering, so shares are biased (they exclude unsold bags). — [CoinGecko Research](https://www.coingecko.com/research/publications/pump-fun-traders-are-making-a-comeback)
- **Earlier Dune snapshot (Jan 2025):** of >13.4M Pump.fun wallets, 55,012 realized >= $10K profit and 294 realized >$1M; Pump.fun co-founder countered ~30% of wallets placed only a single sell order (not human), and post-bonding Raydium buys are excluded from PnL. — [Decrypt](https://decrypt.co/300403/pump-fun-traders-millionaires) (via search summary)
- **March 2026 Dune dashboard (@oladee):** ~1.4M wallets, 49–50.6% lost money, ~96% finished the month in the red or under $500 profit (via search summary). — [Cryptometer](https://www.cryptometer.io/news/pump-fun-data-shows-most-traders-havent-locked-major-gains/)
- **Inflation of apparent skill via manipulated tokens:** an arXiv study of 34,988 tokens (ETH, BNB, Solana, Base) found 82.8% of high-return (>100%) tokens show artificial-growth evidence (wash trading etc.). Implication: high returns on a token can be manufactured, so wallets that bought "winners" may have been inside the scheme. — [arXiv 2507.01963](https://arxiv.org/abs/2507.01963v2)
- **Nansen's own robustness approach:** requires multiple windows (30/90/180/all-time) and token diversity/"performance through downturns" as consistency criteria, which is a form of multi-window persistence screening (formula undisclosed). — [Nansen Academy](https://academy.nansen.ai/articles/2132837-smart-money-101)

### Inferences (not sourced to tools; standard statistics applied to this problem)
- A fixed "win rate >= learned bar" over only 10 closed trades has huge sampling error (a 10-trade 70% win rate has a 95% CI of roughly 35%–93%). Beta-binomial/Bayesian shrinkage toward the population win rate, or a lower-confidence-bound score (e.g. Wilson/Beta lower bound), would rank 12-trade 100%-win-rate wallets below 80-trade 62% wallets, as intuition suggests.
- Because memecoin returns are heavy-tailed, per-trade ROI should be evaluated with bootstrap/permutation tests on trade PnL (or on per-token PnL), and a wallet's lower-bound expected PnL per trade (after shrinkage) is more defensible than its realized sum.
- With thousands of candidate wallets, the best-looking wallets are partly selected luck (multiple-comparisons / winner's curse). The proper test is out-of-sample: score on window T, evaluate on T+1 (like the Hyperliquid design), and measure rank correlation and top-decile forward PnL. GodsEye already has trade history from its own copied trades, so it can run this walk-forward test internally, and should treat the Hyperliquid rho=0.52 as an upper bound for memecoins (different market; no evidence either way found).
- Profit concentration (GodsEye's 50%-of-profit rule) is a sound heuristic; Solana Tracker's token-level cap and MadeOnSol's "PF > 4 is suspicious" corroborate. A smoother alternative is a Herfindahl/top-3-share or "PnL excluding best trade stays positive" check.
- Risk-adjusted/drawdown metrics (Solana Tracker exposes drawdown, streaks, best/worst days) are exposed by at least one vendor but I found no evidence on their predictive value.

### Gaps
- No rigorous study found on persistence of Solana memecoin wallet PnL (month-to-month win/loss), nor on whether smart_degen/Nansen Smart Trader tags predict forward returns.
- No study quantifying survivorship bias in leaderboards (wallets that blow up or rotate addresses vanish).
- No Bayesian-shrinkage or bootstrap implementation found in any commercial wallet tool; the only luck-vs-skill content is practitioner heuristics (profit factor, percentiles), unbacktested.
- The skillselion "wallet-profiling" skill page that reportedly separates skill from luck did not return content; could not review.
- Full text of Markovich et al. not read.

## 3. How should PnL be computed correctly for memecoins, and what are common PnL-inflation pitfalls?

### Takeaway
Tools disagree on PnL for the same wallet because of undocumented choices (average cost vs FIFO, transfers, token-to-token swaps, fees, unrealized valuation, excluded positions). The documented conventions are: average-cost basis (Nansen, Bitquery), SOL/stablecoins treated as quote assets, and "strict" filtering of positions where sells exceed recorded buys (Solana Tracker). I found no vendor that documents fees/tips/failed-tx handling, so best practice here is mostly inference.

### Cited Findings
- **Nansen:** average-cost basis updated after every transaction (weighted average on buys); realized = sale price minus avg cost; counts all on-chain transfers, not just DEX trades; a transferred position carries its cost basis to the receiver at the price at transfer time, and sender books realized profit (Nansen notes this is debated); token-to-token swaps valued by the counterparty leg's implied price, market price only as fallback. Page does not address fees, airdrops or spam tokens. — [Nansen PnL guide](https://www.nansen.ai/post/understanding-nansens-pnl-tracking-a-guide-for-crypto-traders)
- **Solana Tracker PnL v2:** SOL and stablecoins are quote assets, excluded from positions. Three modes: `strict` (default; excludes positions where recorded sells exceed recorded buys, i.e. tokens that arrived via transfer/airdrop/missed history), `adjusted` (keeps them with an "adjusted cost basis", method undisclosed), `raw` (no filtering). Coverage only from December 2023; wallets not indexed on demand. Fees/transfers and win/loss definitions undocumented. — [Solana Tracker PnL v2 overview](https://docs.solanatracker.io/guides/pnl-v2/overview.md)
- **Bitquery wallet-PnL recipe:** average cost; on sell, realized += amount x (sell price - avg cost) with proportional cost-basis reduction; unrealized from open qty at current price; win rate = profitable trades / total trades. — [Bitquery wallet PnL docs](https://docs.bitquery.io/docs/trading/crypto-trades-api/wallet-pnl/)
- **Fees in cost basis:** a Solana PnL-tools guide states fees are typically folded into cost basis (buy 1 SOL at $100 + $0.50 fee => basis $100.50). Secondary source. — [MadeOnSol PnL tools](https://madeonsol.com/blog/best-solana-pnl-tracking-tools)
- **Discrepancies between tools:** a developer reported their own PnL/win-rate numbers significantly differed from Nansen's and that they did not fully understand Nansen's wallet-action classification rules (anecdotal, via search summary). — [MadeOnSol PnL tools / search summary](https://madeonsol.com/blog/best-solana-pnl-tracking-tools)
- **Realized-only blind spots:** CoinGecko's study explicitly counts only realized PnL, so holders who never sold are excluded, which "understates losses"; USD valuations for illiquid memecoins may be missing, stale or distorted; bots and wash trading not filtered. — [CoinGecko Research](https://www.coingecko.com/research/publications/pump-fun-traders-are-making-a-comeback)
- **Post-bonding exclusion:** Pump.fun's co-founder noted buys after bonding to Raydium are excluded from some PnL datasets (Dune pump.fun-only tables), so such analyses misstate wallets that trade across the migration. — [Decrypt](https://decrypt.co/300403/pump-fun-traders-millionaires) (via search summary)
- **Arbitrage/bot filtering:** Solana Tracker defaults excludeArbitrage=true, because arbitrage wallets otherwise pollute rankings. — [Solana Tracker leaderboards](https://docs.solanatracker.io/guides/pnl-v2/leaderboards.md)
- **Wash trading inflates volume/liquidity impression:** Bitquery (Apr 2026) traced fake volume on a memecoin to 3 wallets; one seeded ~200 bots with 0.5 SOL each to wash-trade >$500K volume in 12 hours. Wash volume makes exit prices unrealistic and wallet PnL against such pools unreliable. — [Bitquery: Solana volume numbers are a lie](https://bitquery.io/blog/solana-volume-numbers-are-a-lie)

### Inferences (best practice, not documented by any single source)
- Correct memecoin PnL should be computed in SOL as well as USD (USD-only PnL conflates token trades with SOL price moves; Solana Tracker also converts from USD snapshots, so SOL-denominated views are derived).
- Must-haves: (a) cost basis including network fee, priority fee, Jito/validator tips, and DEX/pool fees and bonding-curve fee; (b) failed transactions still cost fees and should be a debit; (c) tokens received via transfer/airdrop should have zero or flagged cost basis, not market value at receipt (otherwise a later sale shows pure profit; the "strict" mode partly addresses this); (d) token-to-token swaps should be split into sell of leg A and buy of leg B at SOL-equivalent value; (e) unrealized bags should be marked at a liquidity-aware exit price (price impact of selling the full position against the pool), and untouched dead/rugged tokens at zero, not at cost basis and not at the last trade price; (f) bonding-curve-to-AMM migration must be linked as one token lifecycle.
- A "realized-only" ranking rewards wallets that sell winners and hide losers in unsold bags (survivorship within a wallet). Realized + haircut unrealized, or separately reporting "bags held at -90%+", is more honest. GodsEye's 30-day realized USD PnL is exposed to this.
- Scoring metrics should be computed per token position (not per swap), since partial sells and DCA make per-swap win rates meaningless.

### Gaps
- No vendor documentation found on fee/tip/failed-tx handling, airdrops, or zero-valued bag treatment for GMGN, Cielo, Axiom, Photon, BullX, Birdeye.
- No source quantifying how much each pitfall inflates PnL.
- Nansen-style "transfer = realized sale" treatment is described but I found no analysis of how it distorts memecoin leaderboards.

## 4. How do pros separate insiders/snipers/bundlers from "followable" traders (entry latency relative to launch, who can be copied)?

### Takeaway
Detection heuristics center on block offset from token creation (0-3 blocks = sniper), same-block/atomic multi-wallet buys with a common funder (bundler), and direct funding/transfers with the deployer (insider). Evidence indicates snipers exit in seconds to minutes, so a follower cannot take the same trade. The one academic cohort paper (2607.02795) had its numerical results withdrawn on 5 Oct 2026.

### Cited Findings
- **Mobula heuristics (practitioner docs):** Sniper = buys within ~0-3 blocks after creation, with signals: fresh wallet funded shortly before launch, high priority fees/bundle usage. Bundler = cluster of 3+ wallets with: several wallets buying in one atomic transaction, common funder, same-block buys, near-identical buy amounts (e.g. 0.5 SOL), later consolidation of tokens to one wallet. Insider = direct transactions with deployer, funding from dev/insider wallets, buying before public announcement, timing correlated with team wallets (no numeric thresholds). Holdings-based risk table: top-10 holdings <25% green, 25–40% yellow, >50% red; snipers combined >20% red; bundler cluster 10+ wallets red. — [Mobula: detecting snipers/bundlers](https://docs.mobula.io/almanac/detecting-snipers-bundlers.md)
- **Pine Analytics "Exit Liquidity Machines" (industry report, unverified):** deployer-funded same-block snipers on pump.fun, filter = block offset 0 AND direct SOL transfer between deployer and sniper wallet (one hop only). Over ~1 month: 15,000+ SOL net realized profit, 15,000+ tokens, 4,600+ sniper wallets, 10,400+ deployers, covering only ~1.75% of pump.fun launches (lower bound; multi-hop funding missed). 87% of snipes profitable (per snipe, not per wallet); typical profit per wallet 1–100 SOL, outliers >500 SOL; >55% of snipes fully exited in <1 minute, ~85% within 5 minutes, >11% within 15 seconds; >90% used one or two sell swaps. Activity concentrated 14:00–23:00 UTC. Authors claim unfiltered data shows >50% of tokens are sniped in the creation block (unfiltered figure, not high-confidence). — [Pine Analytics](https://pineanalytics.substack.com/p/exit-liquidity-machines)
- **arXiv 2607.02795 (Kamat, submitted 2 Jul 2026; v4 revised 5 Oct 2026):** two-stage pipeline (earliest buyers per launch, then union-find on co-occurrence graph) found 1,012 persistent cohorts (2–12 wallets, 2,965 addresses) in 166,098 launches over ~13 days. The v4 abstract says buyer records included sell transactions and missed many buys, so "all numerical results below are withdrawn pending a corrected analysis." Method is reusable; numbers are not. It reports no returns/PnL. — [arXiv 2607.02795](https://arxiv.org/abs/2607.02795)
- **Solana has no global public mempool**, so same-block sniping is mostly done by pre-funded wallets/Jito bundles or deployer-linked wallets (Pine's reasoning). — [Pine Analytics](https://pineanalytics.substack.com/p/exit-liquidity-machines)
- **Bitquery token checker** uses holder distribution and "received tokens without buying" as insider indicators, only for tokens created in the last 8 hours. — [Bitquery pump.fun token sniffer](https://docs.bitquery.io/pumpfun-token-sniffer/)
- **Copy-latency reality (vendor-sourced):** RPC vendors say slippage grows with every ms of latency and the profitable copy is the one landing near the leader's price; Odinbot says 15% of its copy trades land in the same block, while "most others hit within one to two seconds." Self-interested sources; no independent measurement of leader-vs-copier fill gap. — [RPC Fast](https://rpcfast.com/blog/how-to-build-a-solana-copy-trading-bot); [Decrypt on Odinbot](https://decrypt.co/314700/how-solana-copy-trading-platform-odinbot-is-achieving-zero-block-latency)
- **Kolscan-style caveat:** seeing a trade in a feed means entering later, often at a worse price; multiple wallets per trader and unlabeled wallets are common. — [Kalkine](https://kalkinemedia.com/education/guides/kolscan-how-solanas-smart-money-gets-ranked)
- **Public identity + adverse selection:** in Hyperliquid data, live activity of top wallets predicts short-horizon returns, but identity visibility creates adverse selection for counterparties (copiers become the uninformed side if latency is high). — [arXiv 2608.04373](https://arxiv.org/abs/2608.04373)

### Inferences
- "Followable" can be defined operationally as: wallet's median entry delay after token creation (blocks or seconds), median entry market cap at the wallet's fill, and share of buys placed within N blocks. A wallet whose profit comes mostly from buys within the first ~3 blocks, or from tokens where it was funded by/linked to the deployer, is not followable by a bot with ~1–2 s latency, since by then the price has moved and the leader is exiting (Pine: >55% exits < 1 min).
- GodsEye's tag set (insider/lucky/proven/bot) maps to this; evidence supports splitting by entry latency distribution rather than by a binary "insider" flag. Keeping launch snipers labelled "insider" (per user's memory note that copying insiders is fine) is compatible, but their PnL should be re-scored on a replayed copy-fill (entry price after added delay and slippage) rather than on the leader's own fills. That "replay PnL" is the most direct test of followability and is not offered by any tool I found.
- One-hop deployer-funding checks undercount; multi-hop funding clusters (common funder, same funding amount/time) are needed. Bundler/sniper detection thresholds from Mobula are heuristics, not validated.

### Gaps
- No validated, published false-positive/false-negative rates for any sniper/bundler/insider detector.
- No independent data on leader-vs-copier fill gaps on Solana or how it decays with delay.
- The numerical findings of 2607.02795 are withdrawn; no corrected version seen.
- Pine's 87% win rate is per snipe on a self-defined high-confidence subset (selection bias).

## 5. Categorization schemes (sniper, early bird, swing, bot, KOL, whale, etc.)

### Takeaway
Labels fall into three families: identity-based (KOL, fund, exchange, developer), behavior-based (sniper, bundler, rat/insider, bot, arbitrage, early buyer, high-win-rate "smart degen"), and size-based (whale, memecoin whale). Only Nansen and Solana Tracker publish enough to see the structure; no vendor publishes a hold-time based swing/scalp taxonomy I could verify.

### Cited Findings
- **GMGN:** smart_degen (performance), renowned/KOL (identity), sniper (launch buyer), bundler, rat_trader (insider), plus fresh-wallet ratio; third-party summaries describe GMGN as labelling snipers, early buyers, high-win-rate traders and known bots, and criticize labels as possibly reflecting "one good run" (vendor-biased source). — [gmgn-cli README](https://cdn.jsdelivr.net/npm/gmgn-cli@1.5.2/Readme.md); [MadeOnSol comparison](https://madeonsol.com/blog/nansen-vs-gmgn-vs-cielo-smart-money-solana)
- **Nansen:** performance tiers by PnL window (30D/90D/180D/All-Time/2Y Smart Trader), Smart Fund (VC, hedge, liquid funds), Memecoin Whale (>0.1% supply), Top Pump.fun Memecoin Creator (top 5%). Retired labels covered older LP/airdrop labels. — [Nansen Academy](https://academy.nansen.ai/articles/2132837-smart-money-101); [Nansen: Solana live](https://nansen.ai/post/solana-live-on-nansen)
- **Solana Tracker identity tags:** KOL, bot, arbitrage, exchange, pool, developer, platform, SNS; leaderboard can be filtered by trading terminal (axiom, bloom, photon). — [Solana Tracker PnL v2 overview](https://docs.solanatracker.io/guides/pnl-v2/overview.md); [leaderboards](https://docs.solanatracker.io/guides/pnl-v2/leaderboards.md)
- **Mobula:** sniper / bundler / insider / dev (deployer) as holder-classification roles. — [Mobula](https://docs.mobula.io/almanac/detecting-snipers-bundlers.md)
- **Activity flags (MadeOnSol API, vendor-specific):** `is_heating_up` and `is_cold` measure recent activity, not skill. — [MadeOnSol profit factor](https://madeonsol.com/blog/profit-factor-percentile-rank-kol-wallet-selection-solana)

### Inferences
- A useful scheme for a copy bot combines axes rather than a flat list: (1) identity (KOL/fund/exchange/dev/unknown), (2) entry-timing profile (same-block / first-minute / early-curve / post-migration), (3) hold-time profile (<1 min scalper, minutes-hours swing, days hold), (4) funding-graph (deployer-linked / bundle cluster / independent), (5) automation (bot signature: regular timing, many tokens/day, uniform size). GodsEye's insider/lucky/proven/bot tiers mix axes (insider = timing/funding, lucky = statistics, proven = statistics, bot = automation); separating them would let a wallet be, e.g., "insider-timing + statistically proven".
- KOL wallets carry conflict-of-interest risk (promotion, petition allegation), so a KOL label should add a risk flag rather than quality credit.

### Gaps
- No verified vendor taxonomy for "early bird", "swing", "whale" in Solana memecoin trackers; those terms appear only informally.
- Axiom/Photon/BullX label systems not documented in sources found.
