# Bubblemaps (bubble maps) as a product and data source on Solana, plus equivalent cluster-data tools (as of 2026-10-27)

Scope note: public GET requests to docs and web search only. No sign-up, no API call, no key. The Bubblemaps docs are Mintlify pages and the OpenAPI spec (v0.3.2) was read directly; page text was returned through a summarising fetch tool, so quotes below are as that tool returned them and the spec itself has no `description` fields (only `title`s). The Pro platform (pro.bubblemaps.io) and Bubblemaps Terms (Notion) could not be read. Items from the earlier notes (`detection_tooling.md`, `wallet_clustering.md`) are not repeated unless corrected or extended.

## 1. What does a bubble map show, and how does Bubblemaps decide wallets are connected?

### Takeaway
A bubble map draws the top holders of one token as bubbles sized by holdings, with links where on-chain transfers occurred between them; connected groups are coloured as clusters. Bubblemaps documents the idea (any on-chain transfer links two holders; "bundle" = launch-time temporal set; "cluster" = structural, persistent set) but publishes no thresholds, time windows or algorithm, and its own docs disagree slightly on whether only gas-token transfers count. The API's field named `bundles` is NOT the launch-bundle concept: it is the share held by the 10 largest clusters.

### Cited Findings
**Base object and visuals**
- V2 app map shows the top 250 holders as 250 bubbles; bubble size = amount held; "If two bubbles are linked, it means there has been an on-chain transfer between those holders"; transfers can be of any token and in some cases cross-chain; links can be filtered by token or $ value. Contract and exchange bubbles are hidden by default. — [wiki: How does it work?](https://wiki.bubblemaps.io/bubblemaps-v2/how-does-it-work.md)
- The same page gives no formal cluster definition (clusters are linked bubbles that "have sent funds to each other"), does not name data sources or node colours. — [wiki: How does it work?](https://wiki.bubblemaps.io/bubblemaps-v2/how-does-it-work.md)
- Supernodes (very high transaction volume) are limited: "even if two super nodes are connected, they won't show links on the map". The API says relationships between two supernodes "are ignored" while supernode-to-non-supernode relationships are kept; `is_supernode` "means that the node has a high volume of transfers (threshold may vary)". — [wiki: How does it work?](https://wiki.bubblemaps.io/bubblemaps-v2/how-does-it-work.md); [API: subgraph](https://docs.bubblemaps.io/data/api/relationships/subgraph.md); [API: map](https://docs.bubblemaps.io/data/api/tokens/map.md)
- Premium V2 (for $BMT holders) lists: P&L computation, cross-chain analytics, AI models to interpret clusters, and maps with the top 1,000 holders. No price on the page; Intel Desk and API not mentioned there. — [wiki: Premium](https://wiki.bubblemaps.io/bubblemaps-v2/premium.md)

**Connection rule (earlier blog) vs docs**
- Blog rule: two wallets are linked if at least one historical transaction between them in the chain's gas token (SOL on Solana); only the top 250 holders are loaded; a "native token" mode shows the token's own transfers. — [Bubblemaps blog: Find Deeper Connections](https://blog.bubblemaps.io/find-deeper-connections-between-wallets/) (already in earlier notes)
- Current wiki and API wording is broader: transfers "can involve any token"; API relationships are grouped by `(from_address, to_address, token_ref)`, and by default only transfers of "indexed" tokens are included (`context_token_key` can force one more token in). — [wiki: How does it work?](https://wiki.bubblemaps.io/bubblemaps-v2/how-does-it-work.md); [API: subgraph](https://docs.bubblemaps.io/data/api/relationships/subgraph.md)
- Indexed-token mechanism: Bubblemaps keeps "a limited list of 'indexed' tokens"; maps only consider transfers of indexed tokens, so non-indexed token transfers do not create clusters on other tokens' maps; a token's own map always includes its own transfers even if not indexed (`is_indexed` is a field of `TokenMetadata`). Criteria for being indexed are not given. — [API: token model](https://docs.bubblemaps.io/data/api/token-model.md); [OpenAPI](https://docs.bubblemaps.io/openapi.json)

**Magic Nodes**
- Purpose: reveal connected clusters the default map misses by expanding beyond top holders to include addresses that hold 0 of the token (intermediaries such as an address that funds several holders' gas, a deposit address several holders send to, or a wallet that sent everything away). No thresholds given. — [wiki: Magic Nodes](https://wiki.bubblemaps.io/bubblemaps-v2/magic-nodes.md)
- API: magic nodes are "computed and used in the relationships, score, and clusters"; disable with `use_magic_nodes=false` (default true). Nodes not shown on the map "are not considered in the relationships, score, and clusters computation" per the map page. `is_shown_on_map` "is based on the default visibility state on our main app". — [API: map](https://docs.bubblemaps.io/data/api/tokens/map.md)

**Time Nodes**
- Exchanges and contracts (hidden by default) are split into one abstract node per time window; "Other wallets are only connected if they interacted with the same exchange during that window." No numeric window length or threshold is defined; examples mention wallets funded in "tight time windows" and buys "in the first 30 minutes after launch". Time nodes render as solid coloured bubbles with a logo. — [wiki: Time Nodes](https://wiki.bubblemaps.io/bubblemaps-v2/time-nodes.md)
- API wording: time nodes are "temporal groupings of transfers through CEX, DEX, or whitelisted contracts" used in cluster computation (`use_time_nodes`, default true). — [OpenAPI](https://docs.bubblemaps.io/openapi.json); [changelog 2026-05-22](https://docs.bubblemaps.io/data/api/changelog/2026-05-22.md)
- Implication in their own examples: this is how a ring funded from the same CEX in a narrow window gets linked despite no common upstream wallet (consistent with the $AVA case in the earlier notes).

**Bundle vs cluster (definitions)**
- Bundle: "A set of wallets that transacted together during the token launch" (same block or same snipe window, temporal link). Cluster: "A set of wallets linked by on-chain behavior over time" (shared funding, coordinated transfers, recycled addresses; cross-token recurrence). Bundle detection window "Seconds to minutes at launch"; cluster "Days, weeks, or months". Only numeric threshold: bundle holding "10%+ of total supply" is a major red flag. Organic bundles are "Rare — usually suspicious"; organic clusters exist (friends withdrawing from the same exchange). Example: 18 wallets bought 0.5-2% each in the first two blocks, no shared funding, together 22% (a bundle, no cluster); 30 wallets funded by the same deployer three months earlier, buying at different times, together 19% (a cluster, no bundle). — [Bubblemaps blog: Bundle vs Cluster](https://blog.bubblemaps.io/whats-the-difference-between-bundle-cluster-2/)
- Practitioner thresholds in Bubblemaps' own guide: a single cluster above "20-30% of supply" is a danger sign (checklist uses 20%); top-10 wallets sharing one colour is "a serious warning sign". — [Bubblemaps blog: spot a rug pull](https://blog.bubblemaps.io/how-to-spot-a-rug-pull-using-bubblemaps-before-it-happens/) (vendor guidance, not validated)
- Bubblemaps' guide states limits: on-chain only; does not reveal contract backdoors (mint functions, transfer restrictions, hidden admin keys), suggests TokenSniffer/GoPlus for that; blind to off-chain shilling; a well-distributed token can still have a liquidity lock expiring soon. — [Bubblemaps blog: spot a rug pull](https://blog.bubblemaps.io/how-to-spot-a-rug-pull-using-bubblemaps-before-it-happens/)

**The published "cluster %" metrics (API names and definitions, all shares in [0,1])**
- `supply_stats.cexs`, `dexs`, `contracts`: "Total supply held by CEXs, DEXs, contracts, etc..." — [API: metrics](https://docs.bubblemaps.io/data/api/tokens/metrics.md)
- `supply_stats.fresh_wallets`: "Total supply held by wallets that are less than 10 days old". — [API: metrics](https://docs.bubblemaps.io/data/api/tokens/metrics.md)
- `supply_stats.top_10_adjusted`: "Total supply held by the 10 largest entities, whether they're standalone holders or clusters", "Adjusted to ignore CEXs, DEXs, etc". — [API: metrics](https://docs.bubblemaps.io/data/api/tokens/metrics.md)
- `supply_stats.bundles`: "Total supply held by the 10 largest clusters. Standalone holders are excluded, even if they're the largest holders". NOTE: this is a naming trap versus the blog's "bundle" (a launch-time temporal set); in the API the `bundles` number is a structural-cluster concentration, and no launch-window bundle field exists in the spec. — [API: metrics](https://docs.bubblemaps.io/data/api/tokens/metrics.md); [OpenAPI](https://docs.bubblemaps.io/openapi.json)
- `scores.bubblemaps_score`: "our fine tuned algorithmic score from 0 (less decentralized) to 100 (more decentralized)"; can be `null` "on rare occasions when the algorithm is not applicable". Per the wiki it analyses the top 250 holders excluding CEXs, DEXs and contracts, only considers holders and clusters Bubblemaps detects ("Anything we don't detect won't affect the score"), and weights/thresholds are not published; examples: one 26-wallet cluster at 27.62% scores 22.7; largest cluster 15.64% scores 32.5; one small 1.62% cluster scores 85.4. — [API: metrics](https://docs.bubblemaps.io/data/api/tokens/metrics.md); [wiki: Bubblemaps Score](https://wiki.bubblemaps.io/bubblemaps-v2/bubblemaps-score.md)
- `scores.gini_index`, `herfindahl_hirschman_index`: 0 (equal) to 1 (unequal); `nakamoto_coefficient`: "minimum number of independent entities needed to reach 50% of the supply". — [API: metrics](https://docs.bubblemaps.io/data/api/tokens/metrics.md)
- Cluster object (`ClusterDataV0`): `share`, `amount`, `holder_count`, `holders[]`, `magic_node_count`, `magic_nodes[]`, `time_node_count`, `time_nodes[]` (each `{id, address}`). Magic nodes in clusters were added 2026-09-08; time nodes in clusters 2026-10-16. — [OpenAPI](https://docs.bubblemaps.io/openapi.json); [changelog 2026-09-08](https://docs.bubblemaps.io/data/api/changelog/2026-09-08.md); [changelog index](https://docs.bubblemaps.io/data/api/changelog/index.md)
- Address labels (`AccountAddressDetails`): `label`, `is_paid_label` (true means community-submitted label), `entity_id`, `first_activity_date`, `degree`, `is_supernode`, `is_contract`, `is_cex`, `is_dex`, `inward_relations`, `outward_relations`. Labels "come from our refined database of 1B+ identified addresses" (vendor claim). — [OpenAPI](https://docs.bubblemaps.io/openapi.json); [API: address batch](https://docs.bubblemaps.io/data/api/addresses/metadata-batch.md)

**Other product items**
- Bubblemaps score is shown per token on a new "feed" (Sept 15, 2026 press release) that screens out tokens with insider clusters or bundles before showing them; includes an integrated swap; no thresholds, latency, chain list or API mention. — [The Defiant (Chainwire press release)](https://thedefiant.io/news/press-releases/bubblemaps-sets-a-new-industry-standard-for-catching-rug-pulls-before-they-happen) (company press release)
- Intel Desk: described on the site as an "InfoFi", community-powered research platform; a search summary says submitting a case costs 100 BMT, holders vote with BMT, contributors are rewarded in BMT, and it began as Bubblemaps' own investigations (TRUMP, MELANIA). It is an investigation/reporting product; no API or data access mentioned. — [Bubblemaps Intel Desk](https://bubblemaps.io/intel-desk); [DefiLlama interview](https://defillama.com/research/interview/a-conversation-with-nicolas-vaiman-ceo-and-co-founder-of-bubblemaps) (via search snippet, not fetched)
- Wiki index lists V2 pages: How does it work, Magic Nodes, Time Nodes, Time-Travel, Add addresses, Bubblemaps Score, Swap, Submit labels, Premium, Promote (Bolts, Token profile). Time-Travel: "rewind and explore how a token's distribution looked at any point in its history, from launch to today"; granularity unstated. — [wiki V2 index](https://wiki.bubblemaps.io/bubblemaps-v2); [wiki: Time-Travel](https://wiki.bubblemaps.io/bubblemaps-v2/time-travel.md)

### Inferences
- For a copy-bot, the only API number that approximates "launch bundle share" is none: `bundles` is top-10-cluster share and `fresh_wallets` is "<10 days old" (a coarse proxy, not "bought in launch block"). Launch-window bundling would have to be computed locally from `GROUPED_TRANSFER` data (`first_date`/`last_date`) or from our own gRPC stream.
- Time nodes plus magic nodes mean Bubblemaps links wallets through exchange withdrawals in the same window and through zero-balance intermediaries. Neither is derivable from the holders endpoint alone, which is the value added over a DIY "top holders + first funder" approach. The exact windows are unknown, so results cannot be reproduced locally.
- The doc-level discrepancy (gas-token transfers only in the 2025 blog; any indexed-token transfer in the 2026 docs) suggests the rule changed or the blog is stale; the 2026 docs are the better guide for the API.

### Gaps
- No numeric time-window length, transfer-size threshold, supernode threshold, or the clustering algorithm itself is published.
- Whether cluster share (`ClusterDataV0.share`) excludes CEX/DEX/LP-held amounts is not stated (carried over from earlier notes; `top_10_adjusted` explicitly does).
- Criteria for "indexed" tokens, and whether a fresh pump.fun mint is indexed (see section 2): not documented.
- No independent accuracy measurement (precision/recall) of Bubblemaps clusters on Solana was found; the only comparison pages are review aggregators.

## 2. Bubblemaps Data API: endpoints, auth, credits, rate limits, fields, chains, freshness on brand-new Solana tokens

### Takeaway
The API (OpenAPI v0.3.2, base `https://api.bubblemaps.io`, header `X-ApiKey`) is credit-priced: a full cluster map costs 25 credits, top holders 1 credit, plus add-ons; the only published rate limit is 10k calls/min per IP; plan prices and monthly credit amounts are not published anywhere readable. Solana is supported and "All tokens are supported by default", but docs promise nothing about latency for seconds-old tokens: cache TTL "depends on token age", query time is "a few ms" for cache hits up to a minute, and the V2 wiki says maps are guaranteed refreshed within 6 hours (new tokens "may lag"). There is no webhook or streaming in the spec or docs.

### Cited Findings
**Endpoints, auth, version**
- Base URL `https://api.bubblemaps.io`; security scheme `APIKeyHeader` = `X-ApiKey`; spec title "Bubblemaps Data API", version 0.3.2; spec has no rate-limit or credit text and no field descriptions. — [OpenAPI](https://docs.bubblemaps.io/openapi.json)
- Paths (all under `/v0`): `GET /chains`; `GET /tokens/search?query=` (min length 2; name, symbol or address); `GET /tokens/metadata/{chain}/{token_address}?return_token_stats`; `POST /tokens/metadata` (up to 1000 `TokenKey`s); `GET /tokens/holders/{chain}/{token_address}` (`limit` 80/250/500, `timestamp`, `refresh`, `return_metadata`); `GET /tokens/map/{chain}/{token_address}` (`limit`, `timestamp`, `refresh`, `use_magic_nodes`, `use_time_nodes`, `return_nodes`, `return_relationships`, `return_clusters` default true); `GET /tokens/metrics/{chain}/{token_address}`; `GET /tokens/screenshot/{chain}/{token_address}` (beta; returns `image_url`, `updated_at`); `GET /addresses/metadata/{address}`; `POST /addresses/metadata` (1-2500 addresses); `POST /relationships/subgraph` (2-1000 addresses, optional `context_token_key`). — [OpenAPI](https://docs.bubblemaps.io/openapi.json)
- Chain enum `ChainIdV0` (14): `eth, base, solana, tron, bsc, sonic, ton, avalanche, polygon, monad, hyperevm, arbitrum, robinhood, arc`. This is longer than the earlier notes' list (HyperEVM, Arbitrum added 2026-06-10, Robinhood 2026-07-13, Arc 2026-09-16; Apechain deprecated). Docs warn more chains "will" be added "without notice". — [OpenAPI](https://docs.bubblemaps.io/openapi.json); [changelog index](https://docs.bubblemaps.io/data/api/changelog/index.md); [API: map](https://docs.bubblemaps.io/data/api/tokens/map.md)
- Solana addresses are case sensitive; native token = the constant `"native"`. — [API: token model](https://docs.bubblemaps.io/data/api/token-model.md)
- Maturity: "this is still an early version, that we will build over progressively." — [API: introduction](https://docs.bubblemaps.io/data/api/introduction.md)
- Changelog: 2026-04-29 credit system, self-serve platform, new endpoints launched (switched from a query-seconds system to a deterministic credit system); 2026-05-22 time nodes, new metrics endpoint, deprecations; 2026-06-10 "Improved API response times"; 2026-09-08 screenshots (beta), cluster magic nodes, legacy `/chains` and `/maps` removed, `decentralization_score` / `identified_supply` / `token_stats` removed; 2026-10-16 clusters include the time nodes they contain. — [changelog index](https://docs.bubblemaps.io/data/api/changelog/index.md); [2026-04-29](https://docs.bubblemaps.io/data/api/changelog/2026-04-29.md)
- Old field names that earlier code/notes may reference are gone: use `metrics.scores.bubblemaps_score` instead of `decentralization_score`, `metrics.supply_stats` instead of `metadata.identified_supply`, `stats` instead of `token_stats`. — [changelog 2026-09-08](https://docs.bubblemaps.io/data/api/changelog/2026-09-08.md)

**Credits and limits (this fills part of the earlier gap)**
- Monthly credits depend on subscription; usage resets on the monthly renewal date; each endpoint costs a different amount, some optional params raise it; over-credit gives HTTP 429; separate "10k calls/minute rate limit ... at the IP level". Keys come from the Pro platform. The page lists no prices or plan tiers. — [API: authentication](https://docs.bubblemaps.io/data/api/authentication.md)
- Per-endpoint credit costs: map 25 per request (+50 for `limit=250`, +100 for `limit=500`, +25 `return_nodes`, +25 `refresh`, +50 `timestamp`); metrics 25; top holders 1 (+10 `limit=250`, +25 `limit=500`, +25 `return_metadata`, +25 `refresh`, +50 `timestamp`); subgraph 10 + 1 per address; screenshot 25; token metadata 0.1 (0.5 with `return_token_stats`); supported chains 0.01; address metadata 1 per address. — [API: map](https://docs.bubblemaps.io/data/api/tokens/map.md); [metrics](https://docs.bubblemaps.io/data/api/tokens/metrics.md); [top holders](https://docs.bubblemaps.io/data/api/tokens/top-holders.md); [subgraph](https://docs.bubblemaps.io/data/api/relationships/subgraph.md); [screenshot](https://docs.bubblemaps.io/data/api/tokens/screenshot.md); [metadata](https://docs.bubblemaps.io/data/api/tokens/metadata.md); [chains](https://docs.bubblemaps.io/data/api/chains/supported.md); [address batch](https://docs.bubblemaps.io/data/api/addresses/metadata-batch.md)
- Address metadata (single and batch) "is only available on custom plans". — [API: address batch](https://docs.bubblemaps.io/data/api/addresses/metadata-batch.md); [changelog 2026-04-29](https://docs.bubblemaps.io/data/api/changelog/2026-04-29.md)
- Plan details are linked to `pro.bubblemaps.io/api/plans`; fetching that and `pro.bubblemaps.io` returned only the title "Bubblemaps Pro" (JavaScript app, nothing readable). A search for pricing found nothing. — [Bubblemaps site](https://bubblemaps.io/pricing); [search result: auth doc](https://docs.bubblemaps.io/data/api/authentication.md)
- iFrame product (separate from the Data API): "you won't have to pay a subcription" for basic uses such as a token team showing its own map; multiple plans for exchanges/analytics platforms by volume, customization, chain support, marketing support; custom deals negotiable; needs a `partnerId` (use `demo` on localhost). — [iframe pricing](https://docs.bubblemaps.io/iframe/pricing.md); [introduction](https://docs.bubblemaps.io/introduction.md)

**Freshness, caching, latency**
- "Data can be cached for performance, cache TTL depends on token age." Update time is in the `X-Dt-Update` response header; `refresh=true` bypasses the cache (costs +25 credits on map and holders). The response `metadata` has `dt_update` and `ts_update`. — [API: map](https://docs.bubblemaps.io/data/api/tokens/map.md); [API: top holders](https://docs.bubblemaps.io/data/api/tokens/top-holders.md); [OpenAPI](https://docs.bubblemaps.io/openapi.json)
- "Query duration ranges from a few ms for cache hits, up to a minute for outliers. Most queries should not take more than 15s though." (vendor statement, not measured.) — [API: map](https://docs.bubblemaps.io/data/api/tokens/map.md)
- V2 app: map "guaranteed to have been refreshed within the last six hours, though newly launched tokens may lag" (as returned by the fetch summarising the page; the wording about new tokens should be re-checked on the page). A QuickNode listing says most maps refresh within a few hours. — [wiki: How does it work?](https://wiki.bubblemaps.io/bubblemaps-v2/how-does-it-work.md); [QuickNode listing](https://www.quicknode.com/builders-guide/tools/bubblemaps-by-bubblemaps-team)
- Bubblemaps' marketing says maps show holdings and links "in real time, before anything happens", with no latency figures; its API blog says "up-to-date information" and "historical onchain events". — [Bubblemaps blog: spot a rug pull](https://blog.bubblemaps.io/how-to-spot-a-rug-pull-using-bubblemaps-before-it-happens/); [Bubblemaps blog: Get Started with the API](https://blog.bubblemaps.io/get-started-with-bubblemaps-api/)
- Error semantics for unseen tokens: top-holders/map "All tokens are supported by default" but 404 if no holders are found and 400 for "rare unsupported tokens". — [API: top holders](https://docs.bubblemaps.io/data/api/tokens/top-holders.md)
- Streaming/webhooks: none in the OpenAPI spec (11 REST operations) and none mentioned in the docs index. — [OpenAPI](https://docs.bubblemaps.io/openapi.json); [llms.txt](https://docs.bubblemaps.io/llms.txt)
- A review-aggregator page says Bubblemaps "can load slowly for tokens with many holders" and that "some Solana tokens are not yet indexed" (secondary, no measurement). — [MadeOnSol compare](https://madeonsol.com/compare/bubblemaps-vs-rugcheck)

**Use for bots**
- Bubblemaps' own docs list "trading bots" as a Data API use case and "Telegram monitoring bots" as an iFrame use case. — [Bubblemaps: B2B products](https://docs.bubblemaps.io/introduction.md)

### Inferences
- Cost model for a copy-bot: one `GET /tokens/metrics` (25 credits) or `GET /tokens/map` with `return_clusters=true` (25 credits) per candidate token; a forced-fresh map is 50 credits. At, say, 400 candidate buys/day, a cached-metrics-only approach is ~10,000 credits/day (~300k/month) and a `refresh=true` approach ~20,000/day. Whether any plan includes that is unknown; the monthly credit allotment is the unresolved number.
- The `bubblemaps_score` and `supply_stats` are cheap in credits versus time-travel (`timestamp` +50) and 500-holder maps (+100), so the cost-efficient call is `/tokens/metrics` with defaults.
- Because cache TTL depends on token age (direction unspecified) and `refresh=true` costs extra, a bot should call with `refresh=true` for tokens under a few minutes old and check `X-Dt-Update` / `metadata.ts_update` to log staleness. Whether a pump.fun token only seconds old returns data, 404, or stale data is unmeasured; the docs promise only "all tokens are supported by default".
- Realistic role: asynchronous second-stage check (re-score a held position, or gate an add-on entry at +1 to +5 minutes), not an entry gate for sub-10-second copying, given a stated 15 s typical query time and a 60 s worst case. This echoes the earlier notes' recommendation and is not contradicted by anything found.

### Gaps
- Plan names, monthly prices, monthly credit amounts, and free-tier existence for the Data API: not found (Pro app not readable; no third-party pricing found). The earlier note "price not found" stands.
- Time from mint to first map for a pump.fun/PumpSwap token: no documentation or independent measurement found; this needs an empirical probe (requires a paid key).
- Whether bonding-curve and PumpSwap pool accounts are labelled `is_dex` / excluded from `top_10_adjusted` on Solana: not stated.
- Endpoint-level rate limits (calls/sec), burst behaviour, SLA, uptime: not stated; only 10k calls/min/IP. A review aggregator shows 100% 30-day uptime but that is not an SLA.
- Per-endpoint pages for `search`, `metadata-batch` and `chains` were only skimmed for cost; response example payloads with real Solana values were not seen.

## 3. Equivalent or adjacent tools with cluster / insider / bundle data (API, cost, latency, accuracy vs Bubblemaps)

### Takeaway
Only a few alternatives expose cluster-like data through an API: Birdeye (new `holder-profile`: bundler/sniper/insider/dev tags), Solana Tracker (risk object with snipers/insiders/bundlers; priced), RugCheck (insider graph; schema unverified), GMGN (data API whitelisted/cooperation-only). Helius and Solscan give first-funder primitives, not clusters. Axiom, Photon, Padre, Cielo have bundle/insider UI but no documented cluster API. No source gives a head-to-head accuracy or latency test against Bubblemaps.

### Cited Findings
**Birdeye (new since earlier notes)**
- 2026-04-17 release: `GET /token/v1/holder-profile` (aggregated holder summary: market cap, liquidity, 1h volumes, top-10 concentration, and per-tag breakdown with holder count, hold amount, percent of supply, buy/sell volume, average buy price, unrealized PnL) and `GET /token/v1/holder-positions` (paginated wallet positions, filter by tags, includes first trade time and labels). Tags: `bundler`, `sniper`, `insider`, `dev` (not defined on the page). Solana. "Bundler tag data is accurate for tokens created from 2026-03-01 onwards"; earlier tokens still backfilled. CU cost and plan requirement not stated. — [Birdeye changelog](https://data.birdeye.so/docs/changelog/20260417-release-token-holder-profile-positions-apis)
- Auth/other: `X-API-KEY` header plus `x-chain`; x402 pay-per-request in USDC on Solana without a key exists; tiers per earlier notes. — [Codex migration doc](https://docs.codex.io/migrations/birdeye) (third party); [Birdeye x402](https://docs.birdeye.so/reference/x402) (search result only)

**Solana Tracker**
- Data API plans (EUR/month): Free 10,000 req/mo at 3 req/s; Advanced 50 (200k); Pro 200 (1M); Premium 397 (10M, Datastream WebSocket); Business 599 (25M); Enterprise 1,499 (100M); 30% off annually. — [Solana Tracker pricing](https://docs.solanatracker.io/pricing.md)
- Risk object with `snipers`, `insiders`, `bundlers`, `dev`, `top10`, score 1-10 was documented in the earlier notes (blog article). — [Solana Tracker article](https://www.solanatracker.io/resources/check-solana-token-rug-risk-api)
- Terms: building "applications, bots, dashboards, analytics tools" is permitted; "Redistribution, resale, or sublicensing of raw API data is prohibited without prior written authorization"; displaying "derived data (charts, analytics, aggregations)" in your applications is allowed; no scraping outside the API; developer indemnifies the vendor for bot losses; must not imply endorsement. — [Solana Tracker terms](https://www.solanatracker.io/terms)

## 4. Terms of use: can a trading bot call the API commercially, and can results be redistributed on a public website?

### Takeaway
Bubblemaps' docs positively invite trading bots to use the Data API, but the binding Terms & Conditions (hosted on Notion) and any API licence could not be read, so commercial-use and redistribution rights are unverified. Bubblemaps' own iFrame product is the sanctioned way to show maps publicly, and its docs say custom deals and "case by case" arrangements are handled via email.

### Cited Findings
- Docs name "trading bots that want to fetch and process Bubblemaps data in their own codebases and pipelines" as a Data API use case; "Directly access our data and present it the way you want within your service" is the Data API's stated purpose. — [Bubblemaps: B2B products](https://docs.bubblemaps.io/introduction.md)
- That page contains no formal terms; custom labelling is "case by case"; custom deals and questions go to contact@bubblemaps.io. — [Bubblemaps: B2B products](https://docs.bubblemaps.io/introduction.md)
- The main site footer links Terms & Conditions, Cookie Preferences and Privacy Policy as external Notion pages (contents not retrievable here); no attribution requirement, scraping or redistribution wording seen on the site; copyright "2026 Bubblemaps SAS". — [bubblemaps.io](https://bubblemaps.io/terms)
- The iFrame product requires a `partnerId` and domain whitelisting for deployment; basic usage (e.g. a token team embedding its own map) has no subscription fee; platforms get volume-based plans. — [iframe pricing](https://docs.bubblemaps.io/iframe/pricing.md)
- Address metadata (labels/entities) is restricted to custom plans, which suggests label data is a separately licensed product. — [API: address batch](https://docs.bubblemaps.io/data/api/addresses/metadata-batch.md)
- Comparison (another vendor): Solana Tracker's terms explicitly allow bots and displaying derived data but forbid redistributing or reselling raw API data without written authorisation. Typical, but not evidence of Bubblemaps' terms. — [Solana Tracker terms](https://www.solanatracker.io/terms)

### Inferences
- Calling the API from a trading bot is clearly within the product's intended use. Showing Bubblemaps-derived scores or cluster percentages on the public read-only GodsEye site is a redistribution question that the docs do not answer; the safest interpretations are (a) show only coarse derived flags rather than raw `holders` / cluster membership / labels, (b) use the official iFrame (partnerId) for any embedded map, or (c) get written confirmation from contact@bubblemaps.io. This follows the project's existing public-read-only-redacted policy but is not a legal reading.
- Even if the terms allow commercial use, label data (`label`, `entity_id`, `is_paid_label`) and address metadata are plan-gated; building a public cluster/label view from it would likely need a custom plan.

### Gaps
- The text of Terms & Conditions, any API-specific terms, acceptable-use, data-retention or redistribution clauses: not read (Notion links not retrievable).
- Whether results can be stored, used for model training, or republished: unknown.
- Whether a sub-$X subscription plan exists that permits automated high-frequency calls: unknown (plans page unreadable).
